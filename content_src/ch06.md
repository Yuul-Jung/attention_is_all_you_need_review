## 3.3절 · 위치별 피드포워드 신경망

### @ 원문 요지

1. 인코더·디코더의 모든 층에는 어텐션 서브층 말고 **완전연결 피드포워드 신경망**이 있다.
2. **각 위치에 따로, 똑같이** 적용한다.
3. 선형 변환 두 개 사이에 **ReLU**를 둔다.

```FORMULA
FFN(x) = max(0, x·W₁ + b₁) · W₂ + b₂        … 식 (2)
```

4. 선형 변환은 위치끼리는 같지만 **층마다 다른 가중치**를 쓴다. 커널 크기 1인 합성곱 두 개로 볼 수도 있다.
5. 입력·출력은 **d_model = 512**, 가운데 층은 **d_ff = 2048**이다.

![위치 1~4가 각각 W1(512→2048), ReLU, W2(2048→512)를 거친다](figs/f06_ffn.svg)

**그림 #.** FFN: 위치마다 같은 가중치로 512 → 2048 → 512

| 비교 | 어텐션 서브층 | FFN 서브층 |
|---|---|---|
| 위치끼리 정보 교환 | 함 (여러 위치를 섞음) | 안 함 (위치마다 따로) |
| 하는 일 | 다른 위치에서 정보를 모음 | 모은 정보를 위치 안에서 가공 |
| 가중치 | 층마다 다름 | 층마다 다름, 한 층 안 위치끼리는 같음 |

> **쉽게 말하면** 어텐션이 "회의에서 남의 의견 듣기"라면, FFN은 "자기 자리로 돌아와 혼자 정리하기"입니다. 정리 방법(가중치)은 모두가 같고, 층이 바뀌면 방법도 바뀝니다.

## 3.4절 · 임베딩과 Softmax

### @ 원문 요지

1. 다른 변환 모델처럼, 학습된 **임베딩**으로 입력·출력 토큰을 d_model칸 벡터로 바꾼다.
2. 디코더 출력은 보통처럼 학습된 **선형 변환과 softmax**로 다음 토큰 확률로 바꾼다.
3. 두 임베딩층과 softmax 앞 선형 변환이 **같은 가중치 행렬을 공유**한다.
4. 임베딩층에서는 그 가중치에 **√d_model**을 곱한다.

![가중치 행렬 W 하나를 입력 임베딩, 출력 임베딩, Softmax 앞 Linear가 함께 쓴다](figs/f06_share.svg)

**그림 #.** 가중치 공유: 한 행렬, 세 곳

1. **입력 임베딩 · 출력 임베딩** — 행렬의 한 행(토큰 번호)을 꺼내 512칸 벡터로 씁니다. √512 ≈ 22.6을 곱합니다.
2. **Softmax 앞 Linear** — 512칸 출력을 같은 행렬과 곱해 어휘 전체의 점수를 냅니다.
3. **공유가 되는 조건** — 영어·독일어가 **한 어휘(약 37000개)**를 함께 쓰기 때문입니다(5.1절).

> **쉽게 말하면** 단어를 숫자로 바꾸는 사전과, 숫자를 다시 단어로 바꾸는 사전을 **한 권**으로 쓰는 셈입니다. 가중치가 약 1900만 개 × 2만큼 줄어듭니다.

## 3.5절 · 위치 인코딩

#### @ 이 절에서 할 일

1. **할 일:** 순서 정보를 넣는 식과 그 무늬를 봅니다.
2. **확인할 것:** 사인·코사인을 고른 이유 두 가지.

### @ 원문 요지

1. 순환도 합성곱도 없으므로, 순서를 쓰려면 토큰의 **상대·절대 위치 정보를 넣어야** 한다.
2. 인코더·디코더 맨 아래에서 입력 임베딩에 **위치 인코딩을 더한다.** 둘 다 d_model칸이라 더할 수 있다.
3. 위치 인코딩은 학습형과 고정형 등 여러 가지가 있는데, 이 논문은 **서로 다른 주파수의 사인·코사인**을 쓴다.

```FORMULA
PE(pos, 2i)   = sin( pos / 10000^(2i / d_model) )
PE(pos, 2i+1) = cos( pos / 10000^(2i / d_model) )

pos : 위치    i : 칸 번호의 절반 (0 … 255)
```

4. 위치 인코딩의 각 칸은 사인파 하나다. 파장은 **2π부터 10000·2π까지 등비수열**을 이룬다.
5. **이유 ①** — 어떤 고정 거리 k에 대해서도 PE(pos+k)를 PE(pos)의 **선형 함수**로 나타낼 수 있어, 모델이 **상대 위치**로 참고하는 법을 쉽게 배울 것이라고 가정했다.
6. 학습형 위치 임베딩도 시험했는데 결과가 **거의 같았다**(표 3 (E)).
7. **이유 ②** — 사인 방식은 학습 때보다 **긴 문장으로 늘려 쓸 수** 있을지 모른다.

![위치 0~63, 칸 0~127의 위치 인코딩 값. 왼쪽 칸은 빠르게, 오른쪽 칸은 천천히 바뀐다](figs/m06_pe.svg)

**그림 #.** 위치 인코딩 무늬 (가로: 칸, 세로: 위치)

1. **왼쪽 칸** — 파장이 짧아 위치가 한 칸만 바뀌어도 값이 크게 바뀝니다. 가까운 위치를 구별합니다.
2. **오른쪽 칸** — 파장이 길어 천천히 바뀝니다. 먼 위치를 구별합니다.
3. **가로줄 하나** — 한 위치의 512칸 "위치 지문"입니다. 위치마다 다릅니다.

![칸 한 쌍을 원 위의 점으로 보면, 위치를 k만큼 옮기는 것은 k·ω만큼 회전](figs/f06_rotate.svg)

### @ 이 장 정리

1. **FFN**: 512 → 2048 → 512, ReLU. 위치마다 같은 가중치, 층마다 다른 가중치.
2. **임베딩 공유**: 입력·출력 임베딩과 softmax 앞 Linear가 한 행렬. 임베딩에는 √512를 곱함.
3. **위치 인코딩**: 사인·코사인을 임베딩에 **더함**. 상대 위치를 배우기 쉽고, 더 긴 문장에 쓸 수 있을 것이라는 두 가지 이유.
4. 이 크기로 세면 base 약 63M, big 약 214M. 표 3(65M, 213M)과 근사하게 맞습니다.

### @ 자주 하는 오해

1. **"위치 정보를 이어 붙인다"** — 아닙니다. 같은 512칸에 **더합니다.**
2. **"사인 방식이 학습형보다 성능이 좋다"** — 표 3 (E)에서 거의 같았습니다. 사인 방식을 고른 이유는 **더 긴 문장에 쓸 가능성** 때문입니다.
3. **"FFN은 어텐션 뒤에 한 번만 있다"** — 인코더·디코더 **모든 층**에 하나씩, 모두 12개 있습니다.
