## 5.1절 · 데이터와 배치

### @ 원문 요지

| 항목 | 영어→독일어 | 영어→프랑스어 |
|---|---|---|
| 데이터 | WMT 2014 표준, 문장 쌍 약 **450만** | WMT 2014, 문장 **3600만** |
| 토큰 나누기 | **BPE**, 원문·번역문 **공유 어휘 약 37000** | **워드피스 32000** |

1. 문장 쌍을 **비슷한 길이끼리** 묶어 배치를 만들었다.
2. 배치 하나에 원문 토큰 약 **25000개**, 번역문 토큰 약 **25000개**가 들어간다.

> **쉽게 말하면** 배치를 "문장 몇 개"가 아니라 "토큰 몇 개"로 맞췄습니다. 길이가 비슷한 문장끼리 묶으면 빈칸(패딩)이 줄어 계산 낭비가 적습니다.

## 5.2절 · 하드웨어와 학습 시간

### @ 원문 요지

| 항목 | base 모델 | big 모델 |
|---|---|---|
| 장비 | 한 대에 **NVIDIA P100 GPU 8장** | 같음 |
| step 하나 | 약 **0.4초** | **1.0초** |
| 전체 step | **100,000** | **300,000** |
| 전체 시간 | **12시간** | **3.5일** |

1. base는 논문 전체에서 설명한 하이퍼파라미터를 쓴 모델, big은 표 3 맨 아랫줄 설정이다.
2. 계산 점검: 0.4초 × 100,000 ≈ 11.1시간, 1.0초 × 300,000 ≈ 3.47일. 원문의 12시간·3.5일과 맞습니다.

## 5.3절 · 최적화기와 학습률

#### @ 이 절에서 할 일

1. **할 일:** 식 (3)을 단계별 숫자와 곡선으로 봅니다.
2. **확인할 것:** 최고점이 어디이고 값이 얼마인지.

### @ 원문 요지

1. **Adam**을 썼다. β₁ = 0.9, β₂ = 0.98, ε = 10⁻⁹.
2. 학습률을 학습 내내 아래 식으로 바꿨다.

```FORMULA
lrate = d_model^(−0.5) · min( step_num^(−0.5) , step_num · warmup_steps^(−1.5) )   … 식 (3)
```

3. 처음 **warmup_steps** 동안은 학습률을 **직선으로 올리고**, 그 뒤에는 **step의 제곱근에 반비례해** 줄인다.
4. **warmup_steps = 4000**.

![학습률이 4000단계까지 직선으로 올라 7.0×10⁻⁴에서 최고, 그 뒤 천천히 줄어든다](figs/m08_lrate.svg)

**그림 #.** 식 (3)의 학습률 곡선 (base, 100,000단계)

#### @ 결과 쉽게 읽기

1. **min의 두 항** — 4000단계 전에는 step·4000^(−1.5)가 작아 이쪽이 쓰입니다(직선). 4000단계에서 두 항이 같아지고, 그 뒤에는 step^(−0.5)가 작아 이쪽이 쓰입니다.
2. **최고점** — 4000단계에서 512^(−0.5) × 4000^(−0.5) ≈ **6.99 × 10⁻⁴**입니다.
3. **절반** — 16000단계에서 최고점의 절반(3.49 × 10⁻⁴)입니다. 4배 뒤에 √4 = 2배 줄어듭니다.
4. **d_model^(−0.5)** — 모델이 넓을수록 학습률을 낮춥니다. big(1024)은 base보다 1/√2배입니다.

> **쉽게 말하면** 처음에는 가중치가 엉망이라 크게 움직이면 학습이 튑니다. 그래서 처음 4000단계는 천천히 속도를 올리고(warmup), 그 뒤로는 점점 줄여 세밀하게 맞춥니다.

## 5.4절 · 규제

### @ 원문 요지

1. 원문은 "세 가지 규제를 쓴다"고 쓰고 아래 두 항목을 적었다. Dropout을 두 자리에 쓰므로 이를 나눠 센 것으로 보입니다(원문에 설명 없음).
2. **Residual Dropout** — 각 서브층 출력에, 서브층 입력에 더해 정규화하기 **전에** Dropout을 건다. 또 인코더·디코더 스택 맨 아래의 **임베딩 + 위치 인코딩 합**에도 건다. base는 **P_drop = 0.1**.
3. **Label Smoothing** — 학습 때 **ε_ls = 0.1**을 썼다. 모델이 덜 확신하도록 배우므로 퍼플렉시티는 나빠지지만, **정확도와 BLEU는 좋아진다.**

![위: Sublayer 출력 → Dropout → 더하기 → LayerNorm. 아래: 임베딩 + 위치 인코딩 → Dropout](figs/f08_dropout.svg)

**그림 #.** Dropout을 거는 두 자리

```FORMULA
서브층 출력 = LayerNorm( x + Dropout( Sublayer(x) ) )
```

#### @ 결과 쉽게 읽기

1. **원-핫** — 정답 칸만 1.0입니다. 모델은 정답 확률을 끝없이 1로 밀어붙이려 합니다.
2. **스무딩** — 정답 0.9, 나머지가 0.1을 나눠 가집니다. 지나친 확신을 막습니다.
3. **분배 방식** — 논문은 정확한 분배식을 적지 않았습니다. 위는 흔히 쓰는 방식의 예입니다.

| 지표 | Label Smoothing 효과 | 이유 |
|---|---|---|
| 퍼플렉시티 | 나빠짐 | 정답 확률을 일부러 1보다 낮게 배움 |
| 정확도 · BLEU | 좋아짐 | 지나친 확신이 줄어 일반화가 좋아짐 |

### @ 이 장 정리

1. 영어→독일어 450만 문장 쌍(공유 어휘 약 37000), 영어→프랑스어 3600만 문장.
2. P100 8장: base 10만 단계 **12시간**, big 30만 단계 **3.5일**.
3. Adam + **식 (3)**: 4000단계까지 올리고, 그 뒤 1/√step로 줄임. 최고 약 7.0 × 10⁻⁴.
4. **Dropout 0.1**(서브층 출력, 임베딩 합)과 **Label Smoothing 0.1**.

### @ 자주 하는 오해

1. **"학습률은 고정값이다"** — 아닙니다. 식 (3)으로 단계마다 바뀝니다.
2. **"Label Smoothing은 모든 지표를 좋게 한다"** — 퍼플렉시티는 **나빠집니다.** 원문이 직접 밝혔습니다.
3. **"Dropout을 더한 뒤에 건다"** — 아닙니다. 서브층 출력에 **먼저** 걸고, 그다음 x와 더해 정규화합니다.
